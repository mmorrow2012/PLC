## Logic Implementation — 2026-08-06
<!-- METRICS:logic -->
- **Execution Duration:** 1691.7 seconds
- **Model:** claude-opus-5
- **Turns:** 54
- **Input Tokens:** 7,398,443
- **Output Tokens:** 151,870
- **Estimated Cost:** $5.6791

**Decisions:**
- Built the demonstrator as a genuine soft-PLC rather than an animation: `SoftPlcEngine` runs a 50 ms MAST scan that (1) drives the point machine from last scan's contactors, (2) integrates the railway with last scan's `%QW`/`%Q0.7` image, (3) reads inputs, (4) applies HMI forces to the *input* image, (5) executes `runRailwayLogic()`, (6) applies forces to the output image, (7) publishes the process image. Advancing the plant with the previous scan's outputs preserves real scan causality — a coil written this scan can only move a train on the next one.
- Kept `railwayLogic.ts` pure (process image in, process image out, no timers of its own beyond `%M`/`%MD` accumulators, no React, no ability to move a train) and put every bit of physics in `networkSimulation.ts`. That boundary is what lets the SCADA mimic, the split-flap PIS boards and the ladder monitor all render from one solved state instead of three parallel approximations.
- Modelled the network as 19 axle-counter blocks — one per station throat, one per running section — over the nine required stations, with a real diverging/converging junction at Birmingham North Jn (main via Manchester, branch via Liverpool rejoining at Manchester). Two tracked services (`1S47` London→Edinburgh, `1E23` Bristol→Edinburgh) share `BLK_BHM` and `BLK_EDI`, so block conflicts arise naturally rather than having to be staged.
- Implemented the aspect solver as a four-step ladder (occupied → RED, successor occupied → YELLOW, second-order successor occupied → DOUBLE YELLOW, else GREEN) and derived movement authority from it, including a linear braking curve that reaches standstill exactly at the block joint. The plant separately refuses to let a train cross a joint into an occupied block, which is the overlap protection that makes the interlock genuinely safe rather than advisory.
- Made the four hard-wired axle counters (`%I0.3`–`%I0.6`) overwrite the corresponding entries of the remote evaluator image inside `FB_TrackBlockInterlock`. Because forces are applied to the input image *before* the logic runs, forcing an axle counter really does put the protecting signal back to danger and hold the trailing train — the force panel exercises the interlocking instead of just re-colouring the HMI.
- Interpreted `%I0.7` as point *correspondence* detection (proved and locked in the commanded lie) rather than literally "normal", with a 4 s detection watchdog feeding the SIL4 trip. That keeps the spec's trip-on-FALSE rule intact while leaving the point toggle usable, since the ~2.4 s swing re-proves inside the watchdog window.
- Added route locking to the point machine: a reverse request is only latched into `M_PointReverseCmd` while `BLK_BHM` is clear of axle counts, so a set route can never be pulled from under a train. A train standing at Birmingham also may not depart until detection is proved.
- Graded the timetable against **booked mileage** rather than actual mileage, interpolating Liverpool onto the booked London–Manchester distance. A diversion via the branch therefore surfaces as genuine lateness (extra distance plus an unbooked call) instead of being silently absorbed by the delay calculation.
- Gave the PIS board volume with 31 background services defined as minute-of-hour patterns that re-base onto the current hour, so the board never goes stale no matter how long the demo runs, and layered the two PLC-tracked services on top in a distinct cyan flap colour.
- Compressed simulated time 120:1 (one real second = two simulated minutes) so the full 736 km London–Edinburgh diagram completes in a little over two minutes while the CPU still scans at a true 20 Hz.
- Sampled the store on independent timers for the two expensive views — 100 ms for the ladder monitor, 250 ms for the PIS board — leaving the 20 Hz render path to the mimic, which is the only view that actually needs it. Split-flap cells are keyed by character value so only the characters that changed remount and re-run the flap keyframes.
- Reused the sibling wastewater project's ladder renderer and `#REGION`-parsing ST viewer verbatim where they were domain-agnostic, and wrote a railway-specific `ladderProgram.ts` (5 networks, 21 rungs, 4 FB bodies) against it. Consistency across the portfolio was worth more than a bespoke renderer.

**Verification:**
- `npm install` and `npm run build` (`tsc` strict with `noUnusedLocals`/`noUnusedParameters`, then `vite build`) both succeed with 0 errors.
- Drove the pure logic and plant model headlessly through 6 000 scans (5 simulated hours) in a temporary harness: both services depart on their booked times, run the full diagram at their ATP-limited line speeds, hand over between blocks without deadlock, emergency-brake to standstill when `%I0.0` opens (`%MW0` → 99, `%Q0.7` → 0), and require the documented two-handed recovery. Re-ran with the junction reversed and confirmed `1S47` diverts `SEC_BHM_LIV` → `BLK_LIV` → `SEC_LIV_MAN` and is correctly speed-limited to 120 km/h on the Liverpool–Manchester section. The harness was deleted afterwards.

**Trade-offs / deviations from prompt:**
- `%IW104` is a single channel but there are two trains. It carries the ATP telegram for the lead service; `FB_SpeedSupervision` reads the trailing service's ceiling out of the same static permanent-way speed table (exposed as `_ATP_Limit_T2` on the LD monitor). Applying one train's curvature limit to both would have been the alternative and is less defensible.
- `%I0.1` is implemented as an alternate-action selector (each press toggles the service run latch) so a single pushbutton can both start and stop the timetable, which is what the HMI needs. A safety trip always forces the latch off, so recovery stays deliberate.
- Added `TimetableBoard.tsx` and `LadderDiagram.tsx` beyond the components named in the prompt: the PIS board and the ladder monitor are large enough that leaving them inside `Visualizer.tsx` and `CodeViewer.tsx` would have made both files unreadable. `CodeViewer.tsx` still owns the ladder ⇄ ST tab toggle as specified.
- The `%MW10`–`%MW50` register table publishes eight 5-word frames (tracked services first, then the nearest background departures). The prompt specifies the address range but not the frame layout; the chosen layout is documented in `PLC_LOGIC.md` §2.1.
- Station dwells, turnarounds and the network clock are all in simulated seconds. Terminated services turn round after 15 simulated minutes and work the diagram again, so the demonstrator keeps running indefinitely without operator intervention.
