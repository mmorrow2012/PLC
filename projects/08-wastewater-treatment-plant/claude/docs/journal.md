## Logic Implementation — 2026-08-05

**Decisions:**
- Wrote `wastewaterLogic.st` as four IEC 61131-3 DFBs (`FB_SafetyInterlock`, `FB_LeadLagPump`, `FB_AerationDO`, `FB_WeirGateControl`) plus a `PROGRAM WastewaterPlant` MAST body, then ported it section-for-section into a pure `runWastewaterLogic()` in `wastewaterLogic.ts` (same numbering, same rung order) so the two sources can be diffed — the same pattern the sibling `01`/`02`/`03` claude projects use.
- Kept a hard split between `wastewaterLogic.ts` (control) and `plantSimulation.ts` (process): the logic never reads the plant model and the model never reads %M/%MW, so they communicate only through the process image, exactly as a controller talks to a plant through its I/O cards. This is what makes the `.st` file a faithful description of what actually executes rather than a decorative listing.
- `advancePlant()` is deliberately called with the *previous* scan's output image. Feeding it the current scan's outputs would produce a simulation with no transport delay — a level responding within the same scan that commanded the pump — which would hide exactly the class of race a scan-based controller can suffer.
- Modelled the LD/FBD networks as **data** (`ladderProgram.ts`: contacts, comparison boxes, parallel branches, DFB bodies, coils) with an `evaluateNode`/`evaluateRung` power-flow evaluator, and made `LadderDiagram.tsx` a generic renderer over that structure. A hand-drawn SVG ladder would drift out of sync with the logic the first time a setpoint changed; driving both from the same tag names and constants makes that impossible. Power is threaded left-to-right per rung, so a contact only glows when it is conducting **and** current actually reaches it.
- Derived the ST tab's live-execution highlight from `(* #REGION name *)` markers parsed out of the `.st` source at load time instead of hard-coded line numbers — editing a comment in the ST file can no longer silently rot the highlight.
- Momentary pushbuttons are queued in `pendingPulses` and cleared by the engine *after* the logic runs, guaranteeing every press is seen by a full scan. The parking-garage project hit the inverse bug (a fast click opening and closing inside one 50 ms scan) and solved it with a UI-side minimum-hold timer; queueing in the store is the same fix moved to where it actually belongs.
- Forces are applied to the input image **before** logic execution and the output image **after** it solves — where a real CPU applies them. The scaffold's reference implementation applied forces only post-hoc, which would have made a forced input invisible to the logic that is supposed to react to it.
- Two defects surfaced during headless verification and were fixed rather than papered over. (1) **Unclearable flood trip:** a `%I0.4` trip inhibits the influent pumps, so the equalization basin could only keep filling and the trip could never be acknowledged — added the manual storm bypass penstock (a hand-wound field valve, explicitly not PLC I/O), which is what a real works has for exactly this reason. (2) **Gate never fully seating:** the 1-scan output→plant delay left the gate at 1.25 % when the 4 s close timer expired; commissioned the mechanical travel ~5 % faster than the timer, the same margin you would dial into a real travel-timeout setting.
- Verified with 21 behavioural assertions across six scenarios, driven headless against the standalone-compiled logic + plant model: flood trip → bypass drain → acknowledged reset → restart; E-Stop with full gate seating and contactor mutual exclusion; lead/lag duty rotation on pump-call drop-out; turbidity vetoing discharge without tripping and recovering via coagulant dosing; DO setpoint tracking up and down; manual weir jog overriding the AUTO permit. All 21 pass.
- Tuned the plant constants so the demo is self-driving at the default 22 % inflow (lead pump cuts in ~20 s after start, aeration engages, clarifier fills and the weir cycles) while a 100 % storm still reaches the 6.0 m lag-pump point and eventually the high-high float — every function block is reachable without the operator having to fight the model.

**Trade-offs / deviations from prompt:**
- The prompt's I/O table has **no secondary clarifier level transmitter**, yet `FB_WeirGateControl` is specified to open when "water in secondary clarifier reaches discharge level". Rather than invent an unrequested `%IW` address, the level is passed in as a named process value (`ProcessContext.clarifierLevel`); on real hardware this is one more 4-20 mA channel. Documented in `PLC_LOGIC.md §5`.
- There is no **closed** limit switch for the weir gate (only `%I0.7` fully-open), so the closed position is derived from a 4 s travel timer on the CLOSE contactor — the standard approach for a single-limit-switch gate.
- `I_LSH_AerationA`/`B` are implemented as **inhibits, not trips**: they block influent pumping and force their blower off. Only `%I0.4` is named by the spec as the flooding interlock, and letting one basin's high float shut the whole works down would be poor practice.
- Pump stop / lag drop-out levels (1.0 m / 4.5 m) are not in the spec; they are the hysteresis bands required to stop the contactors chattering at the given 3.0 m and 6.0 m start points.
- A safety trip also rotates the lead/lag duty (the pump call falls). Kept intentionally — the standby pump should take the next start after an abnormal shutdown — and called out in `PLC_LOGIC.md §3.2`.
- Duty rotation is only observable when the basin actually empties below 1.0 m; in a continuously-loaded plant it never does. The HMI therefore also carries an explicit lead/lag swap button, and the demo card explains dropping the inflow slider to zero to watch a natural rotation.
- The ladder monitor samples at 100 ms rather than every 50 ms scan. A network is a few hundred SVG nodes, no operator can read a 20 Hz animation, and a real online monitor polls at a comparable rate — the SCADA mimic keeps the full 20 Hz because its animations need it.
- **Not verified in a real browser**: no Playwright/Chromium is available in this runner, so the UI was validated by a clean `tsc` type-check and production build plus review of the render path, not by driving the page. The control logic and plant model *were* exercised end-to-end headlessly.
